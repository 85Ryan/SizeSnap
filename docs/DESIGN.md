# SizeSnap 1.1 UI

## 审视与方向

现有界面：388px 宽，深森林绿 #26674e，系统无衬线字体，7-13px 圆角；当前窗口、预设列表、编辑表单叠在同一页面。保留一键保存 / 恢复、备份、每窗口撤销及深浅色模式。退休旧图标、过小的行操作和编辑时重复占位的当前窗口卡片。

本轮为视觉及交互重设计，保留存储协议、后台窗口恢复逻辑、字段 ID、字段顺序和所有已有预设。Chrome 扩展没有 SEO 或路由迁移事项。

使用 design-taste-frontend 的审视、排版、状态、对比度与主题规则；营销页 hero、图库、滚动动效、SEO、Lighthouse 网站分数不适用于这枚离线扩展面板，不引入对应结构或依赖。

DESIGN_VARIANCE = 5，MOTION_INTENSITY = 3，VISUAL_DENSITY = 5。macOS 风格的 Web 工具面板，非 Apple 原生组件或 Liquid Glass 实现。继续使用原生 HTML / CSS / ES modules，避免为这枚面板重写框架。

## 视觉约定

- 主色 #28C840，参照常见 macOS 绿色窗口按钮的外观。不同 macOS 版本 / 显示环境可能有所变化，不视为 Apple 官方固定色值。
- 绿色填充搭配 #102915 深色文字；浅色界面上的小号绿色文字使用同色系深色 #17692B，确保可读性。
- 中性底色 #F6F7F8，表面 #FDFEFE；深色分别为 #191C1A 与 #242925。
- SF 系统字体配等宽数字。标题 18px，操作与正文 12-13px，辅助信息 11px。
- 圆角规则：主区域 16px，按钮 / 输入 / 行 10px，内部尺寸示意与小标签 5px。
- 动效仅用于视图出现和按钮按压，约 140ms，尊重 prefers-reduced-motion。
- 层级：固定头部与底部 1；反馈浮层 2；原生 dialog 顶层。
- Phosphor regular 本地图标统一 1 个家族；品牌图标为简单原创几何窗口标记。

## 交互约定

首页展示实际窗口信息与保存入口，预设列表单独滚动，编辑 / 删除保持可发现。正在匹配的预设标记“当前”，仍可再次恢复。

编辑页替换首页内容，固定底部“仅应用尺寸与位置” / “保存预设”，无需滚到表单末尾寻找操作。输入名称、宽高、坐标、窗口状态的原有顺序保留。

快捷尺寸为 16:9 2560×1440、4:3 2560×1920、3:2 2400×1600、16:10 2560×1600、1:1 2560×2560。点击只填写表单，不移动窗口、不立即创建预设；未填写名称时提供相应名称。快捷尺寸会切回普通窗口状态。

“屏幕居中”以当前 Chrome 窗口所在显示器的 workArea 计算，不以主屏或插件弹窗位置为准。启用后，尺寸变化自动重算坐标；手动修改坐标则退出居中。点击已启用按钮可以关闭持续居中。超屏尺寸保留用户输入，应用时由现有恢复逻辑适配。

表单操作不会自动保存。脏表单返回时确认放弃；错误保持可见，成功提示可关闭。导出、导入、撤销和原生删除确认保留。窗口尺寸预览基于真实输入，属于功能示意，不是装饰性的假截图。

## 验收

检查主界面 / 编辑 / 空状态 / 错误 / 删除确认、亮暗主题、减少动态效果、键盘焦点、长名称和长列表。测量实际文本对比度、按钮单行、400×600 面板边界，浏览器自动化回归存储、窗口恢复和新快捷操作。


## 验收结果

- 27 项核心测试通过，包含中心坐标、负坐标、副屏、超屏尺寸和比例精度。
- 18 项真实扩展浏览器检查通过，并在 macOS 可见 Chrome for Testing 窗口验证保存、恢复、撤销和居中。
- 已逐张检查首页、空状态、编辑页的浅色 / 深色截图；编辑页输入单位对齐，底部动作可见。
- 已验证主色按钮、主文本、辅助文本和选中项在两种主题下达到 WCAG AA 4.5:1；尊重减少动态效果。
- 30 个长名称预设不产生水平溢出，返回编辑的键盘焦点正确。
- 图标本地打包，Phosphor 许可证包含在安装包；无新增权限。
- 已检查文案、圆角和主色一致性、单行按钮、载入 / 空 / 错误状态、确认框。
- 技能中的营销页专用条目（hero、图墙、Marquee、GSAP、SEO、网站 Lighthouse 等）因产品类型不适用；无引入这类结构。
- 实际外接屏热插拔和全屏 Space 动画的系统差异延续 README 中的手动验收说明。


## 本地使用约定（1.1.2）

运行源码统一放在 extension/，Chrome 直接加载由 npm run build 生成的 dist/。不生成 ZIP；编辑完成后运行构建，再重新加载扩展。dist 整体由 Git 忽略。首次从旧目录切换到 dist 前先导出预设，再导入新加载的扩展，避免加载路径改变导致的扩展 ID 差异影响数据。旧目录保留为迁移备份，不参与开发。
